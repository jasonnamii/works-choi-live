01 · Connection

연결 설정

이 사이트가 올라가 있는 GitHub 저장소 정보를 입력합니다. 토큰은 이 브라우저에만 저장되며 화면 밖으로 전송되는 곳은 GitHub뿐입니다.

아직 연결을 확인하지 않았습니다.

토큰은 GitHub에서 Fine-grained personal access token으로 발급합니다.
  1. GitHub 우측 상단 프로필 → Settings → Developer settings → Fine-grained tokens → Generate new token
  2. Repository access는 이 사이트 저장소 하나만 선택합니다.
  3. Permissions에서 Contents만 Read and write로 켭니다. 다른 권한은 필요 없습니다.
  4. 만든 토큰을 위 칸에 붙여 넣고 연결 확인을 누릅니다. 자세한 순서는 함께 전달된 설치 가이드에 있습니다.
02 · How it works

추천 로직 한눈에

고객이 설문을 마치면 아래 다섯 단계를 지나 구성 3안이 만들어집니다. 이 콘솔의 편집 항목이 각 단계의 어느 지점을 움직이는지 함께 표시했습니다.

  1. STEP 1

    운영 상품 확정

    전체 상품 중 카테고리별 순위 1~10위, 총 100개만 추천과 카탈로그에 오릅니다.

    편집: 상품 운영 → 순위

  2. STEP 2

    조건 필터

    화면 노출 여부, 인원 대비 최소 주문 수량, 납기, 인쇄 가능 여부, 제외 품목, 공직자 5만 원 기준으로 후보를 거릅니다.

    편집: 상품 운영 → 노출·필드

  3. STEP 3

    점수 매기기

    남은 후보마다 태그 일치, 인기도, 품질 순위, 행사 관련성, 계절 가점을 합산합니다.

    편집: 가중치 · 행사 매핑

  4. STEP 4

    조합 만들기

    서로 다른 카테고리 1~3종을 묶는 모든 조합을 만듭니다. 같은 카테고리 중복은 허용하지 않습니다.

    편집: 시뮬레이터에서 교체

  5. STEP 5

    예산 맞춤 3안

    총예산과 예상 총액의 차이가 가장 작은 순으로 3안을 고릅니다. 3안이 안 나오면 상담 확인 후보로 보충합니다.

    기준: 예산은 목표값

  • 자동 순위 조정워크샵(강의·연수형)은 볼펜을 3순위로 올립니다 · 워크샵(야외·단합형)이 6~8월이면 보온보냉·런치백을 4순위로 올립니다 · 전시(등록 참가자 키트)는 티셔츠·단체복을 3순위로 올립니다 · 명절 선물이 12~1월이면 노트·다이어리를 1순위로 올립니다.
  • 계절 가점우산 5~7월 · 노트·다이어리 10~12월 · 티셔츠·단체복 4·5·9·10월 · 보온보냉·런치백 4~7월에 계절 점수가 붙습니다.
  • 공직자 기준받는 분에 공직자·교직원·언론인이 포함되면 1인 구성가 5만 원 초과 상품과 조합을 제외합니다.
  • 3안 보장조건 그대로는 3안이 안 나올 때, 수량·납기·인쇄를 상담으로 조정할 수 있는 후보를 더해 항상 3안을 채우고 상담 확인 항목을 함께 표시합니다.
  • 정렬 순서예산 차이가 작은 조합 → 예산 안에 드는 조합 → 점수 높은 조합 → 구성 품목이 많은 조합 순으로 우선합니다.

04 · Event mapping

행사별 카테고리 매핑

행사 유형마다 어떤 카테고리를 몇 순위로 내세울지 정합니다. 순위가 높을수록 관련성 점수가 커져 추천에 먼저 올라옵니다. 한 행사 안에서 같은 카테고리는 두 번 고를 수 없습니다.

05 · Catalog curation

카테고리별 상품 운영

위·아래 버튼으로 순위를 바꿉니다. 1~10위는 홈페이지 카탈로그와 추천에 오르고, 노출 구간 아래 대기 상품은 순위를 올리면 자동으로 교대합니다. 상품을 펼치면 가격·수량·납기·태그를 고칠 수 있고, 노출 버튼을 끄면 카탈로그에는 남되 자동 추천에서는 빠져 상담 제안으로만 다뤄집니다.

    06 · Simulator

    추천 시뮬레이터 · 짝짓기

    지금 화면에서 편집 중인 값으로 실제 추천 엔진을 돌립니다. 결과의 각 상품은 규칙이 허용하는 다른 상품으로 바로 바꿔볼 수 있고, 바꾸는 순간 총액과 예산 차이가 다시 계산됩니다.

    조건을 정하고 추천 실행을 누르면 구성 3안이 나옵니다.

    07 · Review & publish

    변경 검토와 적용

    기본값과 달라진 항목만 모아 보여줍니다. 저장하면 이 차이만 설정 파일로 만들어 저장소에 커밋하고, 홈페이지는 다음 방문부터 새 설정을 읽습니다.

      저장하면 GitHub Pages가 사이트를 다시 만드는 1~2분, 방문자 브라우저 캐시가 풀리는 최대 10분 뒤부터 모든 방문자에게 새 설정이 보입니다. 급하지 않은 변경은 시뮬레이터로 충분히 확인한 뒤 한 번에 저장하는 편이 안전합니다.
