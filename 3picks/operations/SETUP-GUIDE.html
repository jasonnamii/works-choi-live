3PICKS · Setup & Operations

설치와 운영 가이드

3PICKS 홈페이지를 GitHub Pages에 올리고, 내 컴퓨터의 운영 콘솔로 상품과 추천 설정을 관리하는 방법입니다. 별도 서버나 데이터베이스 없이 따라 할 수 있게 적었습니다.

받은 것

전달받은 폴더에는 홈페이지, 운영 콘솔, 그리고 콘솔이 저장하는 설정 파일이 함께 들어 있습니다.

index.html고객이 보는 홈페이지 본체입니다.
operations/admin.html운영 콘솔입니다. 새 상품 등록(사진 포함), 상품 정보 전체 수정, 숨김·보관, 행사별 추천 매핑, 카테고리별 노출 상품 10개, 추천 가중치를 조정하고 추천 결과를 미리 시뮬레이션합니다. 웹에 올리지 않고 내 컴퓨터에서만 엽니다.
site-overrides.js콘솔에서 저장한 설정이 담기는 파일입니다. 홈페이지는 열릴 때마다 이 파일을 읽어 기본값 위에 덮어씁니다.
config.js담당자 이름·전화·카카오 채널 주소와 이메일 문의 레이어에 보일 두 담당자의 이름·이메일입니다. 개통 전에 본인 정보로 바꿉니다.
assets/ 외 나머지상품 데이터·이미지·추천 엔진 등 사이트 구성 파일입니다. 직접 고칠 일은 없습니다.

STEP 1GitHub에 저장소 만들기

GitHub는 사이트 파일을 보관하고 무료로 웹에 열어주는 서비스입니다. 계정이 없다면 github.com에서 먼저 가입합니다.

  1. GitHub에 로그인한 뒤 우측 상단 + 버튼 → New repository를 누릅니다.
  2. Repository name에 원하는 이름을 적습니다. 예: 3picks-site. Public을 선택하고 Create repository를 누릅니다.
  3. 만들어진 저장소 화면에서 uploading an existing file 링크를 누릅니다.
  4. 전달받은 3picks-official-site-날짜-시각.zip의 압축을 풉니다. 안의 3picks-site 폴더 내용만 업로드 화면으로 끌어다 놓습니다. 원본 홈페이지 폴더 전체를 올리면 내부 문서와 운영 콘솔이 공개될 수 있으니 사용하지 않습니다.
  5. 아래 Commit changes를 누르고 업로드가 끝날 때까지 기다립니다. 이미지가 많아 몇 분 걸릴 수 있습니다.

STEP 2GitHub Pages로 사이트 열기

  1. 저장소 상단의 Settings 탭 → 왼쪽 메뉴 Pages로 갑니다.
  2. Build and deployment의 Source를 Deploy from a branch로 두고, Branch를 main / /(root)로 선택한 뒤 Save를 누릅니다.
  3. 1~2분 뒤 같은 화면 상단에 사이트 주소가 나타납니다. 형태는 https://계정이름.github.io/저장소이름/입니다.
  4. 주소를 열어 홈페이지가 나오는지 확인합니다. 주소 뒤의 operations/admin.html과 admin.html은 둘 다 404가 나오는 것이 정상입니다.

회사 도메인을 붙이고 싶다면 같은 Pages 화면의 Custom domain에 도메인을 넣고, 도메인 업체에서 안내대로 DNS를 설정하면 됩니다. 나중에 해도 됩니다.

STEP 3저장용 토큰 만들기

운영 콘솔이 설정을 저장소에 기록하려면 본인 계정의 열쇠(토큰)가 필요합니다. 이 저장소 하나에만 쓰기가 되는 제한된 토큰을 만듭니다.

  1. GitHub 우측 상단 프로필 사진 → Settings → 왼쪽 맨 아래 Developer settings로 갑니다.
  2. Personal access tokens → Fine-grained tokens → Generate new token을 누릅니다.
  3. Token name은 알아볼 이름(예: 3picks-console), Expiration은 가능하면 30일 이하로 둡니다. 만료되면 같은 방법으로 새로 만들면 됩니다.
  4. Repository access에서 Only select repositories를 고르고 STEP 1에서 만든 저장소만 선택합니다.
  5. Permissions → Repository permissions에서 Contents를 Read and write로 바꿉니다. 다른 권한은 그대로 둡니다.
  6. Generate token을 누르고, 화면에 한 번만 보이는 토큰 문자열을 복사해 둡니다.
토큰은 비밀번호와 같습니다. 메신저나 문서에 남기지 말고, 콘솔 입력 칸에만 붙여 넣으세요. 유출이 의심되면 GitHub의 토큰 목록에서 삭제하고 새로 만들면 됩니다.

STEP 4운영 콘솔 연결과 첫 반영

  1. 원본 홈페이지 폴더의 operations/admin.html을 더블클릭해 브라우저로 엽니다. 고객 사이트가 아니라 내 컴퓨터에서만 엽니다.
  2. 전달받은 접속 코드를 넣어 잠금을 풉니다.
  3. 연결 칸에 깃허브 아이디(owner)·홈페이지 보관함 이름(repo)·브랜치 main·복사해 둔 토큰을 넣고 연결 확인을 누릅니다. 토큰은 현재 브라우저 탭에서만 보관되며, 탭을 닫으면 다시 입력합니다. 홈페이지에 이 화면보다 최신 설정이 있으면 상단의 「LLM으로 홈페이지 수정한 내용 어드민에 적용하기」 버튼이 빨갛게 깜빡일 때만 직접 불러옵니다.
  4. 아무 항목이나 하나 바꿔 본 뒤(예: 점수 하나) 홈페이지에 반영하기를 누릅니다. 기록에 「반영 완료」가 나오면 성공입니다.
  5. 1~2분 뒤 홈페이지를 새로고침해 바뀐 것을 확인하고, 확인이 끝나면 콘솔에서 값을 되돌려 다시 반영합니다.

콘솔 비공개 원칙

운영 콘솔이 다른 사람 눈에 띄지 않게 하는 규칙입니다. 콘솔 화면 자체에는 비밀 정보가 없고 저장 권한도 본인 토큰이 있어야만 생기지만, 관리 화면이 공개 주소에 노출되는 것 자체를 막는 것이 원칙입니다.

  • 기본: 웹에 올리지 않기 — operations/ 폴더는 저장소에 업로드하지 말고 원본 폴더에서만 엽니다. 공식 전달 ZIP에는 처음부터 포함되지 않습니다.
  • 예외: 꼭 웹에서 써야 한다면 — 여러 사람이 각자 컴퓨터에서 써야 할 때만 업로드합니다. 이때도 접속 코드 잠금과 검색 제외가 걸려 있지만, 주소를 아는 사람의 접근까지 막지는 못한다는 한계를 알고 써야 합니다.
  • 실수로 올렸다면 — 저장소 파일 목록에서 admin.html 또는 operations/ 폴더를 지우고 커밋합니다. 고객 사이트 동작에는 영향이 없습니다.
  • 접속 코드·토큰 관리 — 코드와 토큰은 사이트를 만들어 준 담당자와 운영자만 압니다. 코드 변경이 필요하면 담당자에게 요청하세요.

일상 운영

콘솔 화면 순서대로 쓰면 됩니다. 권장 흐름은 「고치고 → 미리보기로 확인하고 → 한 번에 반영」입니다.

  • 점수 조정 — 추천 점수의 배점을 조정합니다. 확신이 없으면 기본값을 유지하세요.
  • 행사 매핑 — 행사 유형별로 어떤 카테고리를 몇 순위로 추천할지 바꿉니다.
  • 미리보기 — 반영 전에 고객 입장으로 조건을 넣어 구성 3안을 확인하고, 상품을 바꿔가며 짝을 맞춰봅니다.
  • 상품 운영 — 카테고리마다 순위를 조정해 홈페이지에 진열할 10개를 고릅니다. 1~10위는 모두 홈페이지에 보이고, 「자동 추천에 나감」 버튼을 끄면 진열은 그대로 둔 채 자동 추천에서만 빠집니다. 상품을 펼치면 이름·가격·최소 수량·납기·인쇄 방식·공급처·태그·사진까지 전부 고칠 수 있습니다.
  • 새 상품 등록 — 상품 운영 위의 「+ 새 상품 등록」으로 새 상품을 만듭니다. 사진(1~5장)은 파일을 올리면 자동으로 홈페이지 규격으로 변환되고, 반영할 때 설정과 함께 올라갑니다.
  • 복구 — 반영 뒤 문제가 보이면 「직전 설정 불러오기」로 이전 설정을 초안에 불러오고, 내용을 확인한 뒤 다시 반영합니다.
  • 숨김과 보관 — 「숨김」을 누르면 상품이 홈페이지에서 잠시 내려가고 아래 순위가 자동으로 올라와 자리를 채웁니다. 오래 안 쓸 상품은 「보관」으로 보관함 탭에 옮깁니다. 삭제 기능은 없어서 무엇도 사라지지 않고, 언제든 「숨김 해제」·「복원」으로 되돌립니다.
  • 고객 미니 견적 — 고객이 상품을 담으면 화면 아래 견적함에서 수량과 예상 금액을 확인할 수 있습니다. 견적함 머리의 「비우기」는 그 고객이 담은 상품을 한 번에 지우며, 운영 콘솔의 상품 정보는 지우지 않습니다.
  • 모바일 화면 확인 — 600px 이하에서는 상단 메뉴 전체가 본문을 계속 가리지 않고 페이지와 함께 올라갑니다. 상품 레일만 좌우로 넘길 수 있으며, 반영 전에는 모바일에서 글자 잘림·겹침·페이지 가로 스크롤이 없는지 확인합니다.
  • LLM으로 홈페이지 수정한 내용 어드민에 적용하기 — 화면 맨 위의 이 버튼은 홈페이지 쪽 파일이나 설정이 이 화면 밖에서(예: AI 도구로) 바뀐 것이 감지되면 빨갛게 깜빡입니다. 자동으로 덮지 않으니, 깜빡일 때 눌러서 최신 내용을 이 화면에 불러오세요. 이 화면에 반영 전 수정이 있으면 먼저 백업을 권합니다.
  • 홈페이지에 반영하기 — 누르면 홈페이지에 1~10분 안에 반영됩니다. 새로 올린 사진이 있으면 사진부터 순서대로 올라가고 설정이 마지막에 올라갑니다. 반영 전의 수정은 이 컴퓨터 화면에만 있는 초안이므로, 다른 컴퓨터에는 보이지 않습니다.
  • 백업 파일 받기 — 큰 변경 전에는 이 버튼으로 현재 설정을 파일로 내려받아 두세요. 문제가 생기면 담당자가 그 파일로 되돌릴 수 있습니다.

개통 전 확인

실제 손님에게 열기 전에 아래 항목을 본인 정보로 바꿨는지 확인하세요.

  • 홈페이지 맨 아래 사업자등록번호·통신판매업 신고번호 — 임시값이 들어 있습니다. index.html을 GitHub 화면에서 열어 연필 아이콘으로 해당 숫자만 바꿉니다.
  • config.js의 담당자 이름·전화번호·카카오 채널 주소와 이메일 문의 레이어에 보일 두 담당자의 이름·이메일.
  • 미리보기로 대표 행사 두세 개를 돌려 추천이 의도대로 나오는지 확인.

문제가 생겼을 때

접속 코드가 안 맞음코드는 대소문자를 구분합니다. 계속 안 되면 사이트를 만들어 준 담당자에게 코드를 다시 확인합니다.
연결 확인에서 토큰 오류토큰이 만료됐거나 잘못 복사된 경우입니다. STEP 3대로 새 토큰을 만들어 다시 넣습니다.
저장소를 찾지 못함소유자·저장소 이름의 오타, 또는 토큰 발급 때 이 저장소를 선택하지 않은 경우입니다.
반영 시 충돌 안내다른 창이나 다른 사람이 먼저 반영한 경우입니다. 연결 확인을 다시 누른 뒤 반영하면 됩니다.
반영했는데 홈페이지가 그대로브라우저 캐시입니다. 최대 10분 기다리거나 강력 새로고침(Windows Ctrl+Shift+R, Mac Cmd+Shift+R)을 합니다.
사진 올리다가 중단됨설정은 바뀌지 않은 상태이니 안전합니다. 잠시 후 「홈페이지에 반영하기」를 다시 누르면 멈춘 지점부터 이어서 올라갑니다.
맨 위 버튼이 빨갛게 깜빡임홈페이지 쪽 내용이 이 화면 밖에서 바뀌었다는 뜻입니다. 「LLM으로 홈페이지 수정한 내용 어드민에 적용하기」를 눌러 최신 내용을 불러온 뒤 작업을 이어가세요.
새로 올린 상품 사진이 콘솔에서 빈 칸으로 보임사진 파일은 홈페이지 저장소에 올라가 있고 내 컴퓨터 폴더에는 없는 상태입니다. 홈페이지는 정상 표시되며, 콘솔 썸네일만 비어 보이는 것이니 걱정하지 않아도 됩니다.
설정을 전부 처음으로콘솔에서 매핑·가중치의 기본값 버튼을 쓰거나, 저장소의 site-overrides.js 내용을 처음 전달받은 파일로 되돌립니다.
상품 하나하나의 등록·수정·숨김·보관은 콘솔에서 직접 할 수 있습니다. 다만 상품 수십 개를 한꺼번에 갈아끼우거나(원본 상품표 교체), 페이지 구조·문구·디자인을 바꾸는 일은 콘솔 범위 밖이니 사이트를 만들어 준 담당자에게 요청하세요.
