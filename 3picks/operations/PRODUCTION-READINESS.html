먼저 막아야 할 위험

아래 세 가지는 운영 편의보다 우선합니다. 해결 전에는 공식 고객 사이트에 관리 화면을 포함하거나 실제 운영 토큰으로 반영하지 않습니다.

01

관리 화면은 고객 사이트와 분리합니다.

브라우저 안의 접속 코드 화면은 서버 인증이 아닙니다. 공식 전달 번들에서는 운영 콘솔과 이 가이드를 제외하고, 운영 콘솔은 로컬 또는 별도의 보호된 관리 환경에서만 사용합니다.

02

저장소 쓰기 토큰을 브라우저에 오래 보관하지 않습니다.

공용 컴퓨터에서는 사용하지 않고, 저장소 하나의 Contents 권한만 가진 짧은 만료 토큰을 세션 동안만 사용한 뒤 폐기합니다. 장기적으로는 서버 인증이 있는 관리면으로 옮깁니다.

03

반영 성공 메시지만 믿지 않습니다.

현재 자동 검사는 저장 함수의 실제 실행과 새로고침 뒤 원격 상태 보존을 검증하지 못합니다. 반영 후 새 창의 고객 화면, 원격 설정, 기록번호를 함께 대조해야 합니다.

Safe publishing flow

반영은 이 순서로

저장 성공은 끝이 아닙니다. 초안 백업부터 고객 화면 확인과 기록번호 보관까지 한 흐름으로 닫습니다.

  1. STEP 01

    초안 백업

    현재 설정 파일을 내려받고, 바꾸려는 항목과 원래 값을 짧게 적습니다.

  2. STEP 02

    연결 재확인

    저장소·브랜치·계정을 확인합니다. 연결 확인 뒤 입력값을 바꿨다면 다시 확인합니다.

  3. STEP 03

    미리보기

    상품·추천·숨김·순위 결과를 운영 콘솔에서 확인하고 모바일 폭도 점검합니다.

  4. STEP 04

    한 번에 반영

    중복 클릭하지 않고 완료 또는 실패 메시지와 기록번호가 나올 때까지 기다립니다.

  5. STEP 05

    고객 화면 대조

    새 창에서 해당 상품·카테고리·추천을 확인하고 10분 뒤 한 번 더 확인합니다.

When something breaks

문제가 생기면

여러 번 눌러 해결하려 하지 않습니다. 추가 변경을 멈추고, 마지막 정상 상태를 기준으로 영향 범위를 먼저 줄입니다.

01 · STOP

추가 반영 중단

반영 버튼을 다시 누르지 않고 현재 화면과 오류 문구를 보존합니다.

02 · RECORD

증거 남기기

시간·기록번호·바꾼 항목·고객 화면 상태를 캡처합니다.

03 · RESTORE

직전 정상 복구

검증된 설정 백업 또는 Git 이력으로 돌아가고 새 창에서 확인합니다.

04 · LEARN

재발 방지

원인과 놓친 Gate를 적고 자동 검사 또는 운영 절차에 반영합니다.

  • 사진만 올라간 경우설정 파일이 바뀌지 않았다면 고객 화면은 기존 상태입니다. 설정 반영을 반복하기 전 업로드된 사진과 원격 상태를 확인합니다.
  • 설정은 바뀌었지만 화면이 구버전인 경우새 창·강제 새로고침·최대 10분 캐시 시간을 순서대로 확인합니다.
  • 다른 컴퓨터 변경과 충돌한 경우원격 최신 설정을 먼저 불러오고 양쪽 변경을 비교합니다. 한쪽을 통째로 덮어쓰지 않습니다.
  • 운영자 판단이 어려운 경우추가 반영을 멈추고 설치·개발 담당자에게 기록번호와 증거를 전달합니다.
